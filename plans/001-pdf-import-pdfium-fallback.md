## Why this matters

When users import PDFs, standard PDF files generated by tools like Chrome, Word, Acrobat, Canva, or macOS Print-to-PDF often fail to parse in `inkwell_core::PdfFile::open`. Currently, `commands.rs` only falls back to PDFium if the error is specifically `Error::XrefStream`. Any other parse error causes `open_pdf` and `open_pdf_bytes` to fail immediately. In `app.js`, when `open_pdf` / `open_pdf_bytes` throws an error, the catch block sets dummy page dimensions (`595x842`) without setting the PDF bytes in Rust state. As a result, tile rendering returns `"No PDF loaded"`, causing the imported PDF to show up completely blank.

## Steps

### Step 1: Update `commands.rs` to attempt PDFium normalisation on ANY parse error from `PdfFile::open`

In `open_pdf` and `open_pdf_bytes` in `inkwell-app/src-tauri/src/commands.rs`:
Replace the restrictive `match open_res` that only handles `Err(Error::XrefStream)` with a fallback mechanism: if `open_res` returns `Err(_)`, attempt PDFium initialization and `inkwell_pdf::normalise(&pdfium, &bytes)`. If PDFium normalisation produces valid bytes, open those normalized bytes with `PdfFile::open`. Only if PDFium normalisation or loading also fails, return an error.

Target implementation structure:
```rust
let (valid_bytes, pdf_file) = match PdfFile::open(bytes.clone()) {
    Ok(f) => (bytes, f),
    Err(e) => {
        eprintln!("inkwell-core shallow PDF parser error ({e:?}), attempting PDFium normalisation fallback...");
        match inkwell_pdf::init_pdfium() {
            Ok(pdfium) => {
                let norm_bytes = inkwell_pdf::normalise(&pdfium, &bytes)
                    .map_err(|norm_err| format!("Failed to parse PDF with native reader ({e}) and PDFium normalisation failed: {norm_err:?}"))?;
                let f = PdfFile::open(norm_bytes.clone())
                    .map_err(|open_err| format!("Failed to open PDFium-normalised PDF: {open_err}"))?;
                (norm_bytes, f)
            }
            Err(pdfium_err) => {
                return Err(format!("Failed to parse PDF ({e}) and PDFium engine is unavailable: {pdfium_err:?}"));
            }
        }
    }
};
```

Apply this exact logic pattern in both `open_pdf` (line 35) and `open_pdf_bytes` (line 95).

**Verify**: `& "$env:USERPROFILE\.cargo\bin\cargo.exe" check --manifest-path inkwell-app/src-tauri/Cargo.toml` -> exit 0.
