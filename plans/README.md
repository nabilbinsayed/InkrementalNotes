## Findings considered and rejected

- `Micro-optimization of stroke point smoothing`: Not worth doing because current One-Euro filter in `ink.rs` / `ink.js` already runs in sub-millisecond time.
- `Complete rewrite of PDF parsing in JS`: Not worth doing because Rust `pdfium-render` binding is native, faster, and already handles PDF rendering.
- `Switch to Rust-side TileCache for frontend`: Not worth doing now — would require significant IPC redesign. The JS-side tile grid in Plan 010 provides equivalent cache reuse with minimal changes.
- `Background thread pool for tile rendering`: Not worth doing now — the PDFium Mutex serializes access anyway. Performance gains from tile grid (010) will be sufficient.
